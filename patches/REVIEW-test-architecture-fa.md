## ۳. آنچه رد شد (ادعاهای نادرست اسناد)

### ۳.۱ 🔴 ادعای «PHPStan سطح ۹ = صفر خطا» — نادرست است

سند `CHORTKE_PHASE20_GLOBAL_PHPSTAN_ZERO_FINAL_FA.md` می‌گوید ۱٬۱۹۱ خطا به **صفر** رسیده، «بدون baseline، بدون ignore، بدون cast تقلبی».

**بازتولید واقعی من:**

```
پیکربندی اصلی پروژه (phpstan.neon، سطح ۹، app/+core/)
  → 8 خطا   ✗   (نه صفر)
همان تحلیل بدون baseline
  → 8 خطا       (baseline عملاً مرده است)
```

۷ خطا از ۸ در فایل **دست‌نخوردهٔ** `app/Traits/ClientInfoTrait.php:52` است (با استخراج مستقیم از zip اصلی تأیید شد که ویرایش من نیست) — `currentUserId()` باید `int|null` برگرداند ولی `mixed` می‌دهد.

**چگونه عدد صفر ساخته شده؟** سند به دو فایل خروجی استناد می‌کند. آن‌ها را با پیکربندی‌های متناظرشان اجرا کردم:

| پیکربندی مورد استناد سند | تعداد الگوی `ignoreErrors` | نتیجه |
|---|---|---|
| `phpstan-full-run.neon` (→ `phpstan_full.neon`) | ~۴۵ الگو | 0 |
| `phpstan_core.neon` | **~۱۳۰ الگو** | 0 |

اما همان `core/` را بدون هیچ `ignoreErrors` اجرا کردم:

```
core/ با phpstan_core.neon (config مورد استناد سند) :  0
core/ بدون هیچ ignoreErrors                        : 22
خطاهای پنهان‌شده                                    : 22
```

الگوهای ignore به‌قدری فراگیرند که عملاً تحلیل را خنثی می‌کنند — نمونه‌های واقعی از `phpstan_core.neon`:

```
- '#Call to an undefined method .*::#'     ← هر فراخوانی متد ناموجود را می‌بلعد
- '#but returns mixed#'                    ← هستهٔ خودِ سطح ۹ را خاموش می‌کند
- '#Cannot access offset#'
- '#Argument of an invalid type#'
- '#Strict comparison#'
```

قاعدهٔ `'#Call to an undefined method .*::#'` دقیقاً همان کلاس خطایی را حذف می‌کند که PHPStan برای یافتنش وجود دارد.

**حکم:** «صفر خطا» یک عدد ساختگی است. عدد صادقانه **۸ خطا در app+core** و **۲۲ خطای پنهان در core** است. ادعای «بدون baseline و بدون ignore» با محتوای فایل‌های پیکربندی مستقیماً در تناقض است. — این جدی‌ترین یافتهٔ بازبینی.

## ۵. توصیه‌ها (به ترتیب اولویت)

**۱ — اصلاح گزارش‌های فاز ۲۰ (فوری).** ادعای «PHPStan صفر» باید پس گرفته شود. عدد صادقانه ثبت شود: ۸ خطا با کانفیگ اصلی، ۲۲ خطای پنهان در core. اسنادی که واقعیت را وارونه گزارش می‌کنند، بدهی فنی خطرناک‌تری از خودِ خطاها هستند.

**۲ — رفع ۸ خطای واقعی.** `ClientInfoTrait::currentUserId()` با یک `is_int($v) ? $v : null` حل می‌شود (۷ خطا از ۸). سپس `phpstan_core.neon` و `phpstan_full.neon` پاک شوند و الگوهای فراگیر (`.*::`، `but returns mixed`) حذف گردند؛ ۲۲ خطای core به‌صورت واقعی رفع شوند.

**۳ — قابل‌بازتولید کردن سوئیت contract.** سرور جعلی provider باید به‌صورت کد وارد مخزن شود (مثلاً `tests/Support/fake-provider-server.php`)، روی `127.0.0.1` بایند شود نه `8.8.8.8`، و مسیر state از هاردکد `/home/user/zip/...` به مسیر نسبی تغییر کند. بدون این کار، ۲۵ تست دائماً قرمزند.

**۴ — جداسازی وابستگی systemd.** تست chaos باید از یک انتزاع ری‌استارت (اسکریپت قابل تزریق) استفاده کند تا در محیط بدون systemd هم اجرا شود، یا با `markTestSkipped` صریح و مستند رد شود.

**۵ — حذف ۳۳ `assertTrue(true)`.** هرکدام یا به assertion واقعی تبدیل شود یا حذف گردد.

**۶ — پاک‌سازی لایهٔ Python.** ۹۱ تاتولوژی و ۳۰۵ assert مبهم اصلاح شوند؛ برچسب لایه‌ها بین رودمپ v2/v3 یکسان‌سازی شود؛ یا L7 واقعاً با Playwright/Selenium پیاده شود یا از رودمپ حذف گردد.

**۷ — یکپارچه‌سازی ۱۰ فایل کانفیگ PHPStan.** وجود ۱۰ `.neon` با سخت‌گیری متفاوت، امکان «انتخاب کانفیگ سبز» را می‌دهد. یک کانفیگ واحد به‌عنوان منبع حقیقت بماند.
