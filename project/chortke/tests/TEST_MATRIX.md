# الگوی تستی استاندارد چرتکه — Test Matrix Pattern

## اصول
هر بخش از پروژه باید با **هر ۷ لایه‌ی زیر** تست شود. هیچ بخشی بدون پوشش همه‌ی لایه‌ها کامل محسوب نمی‌شود.

---

## لایه‌های تست (هر بخش = ۷ لایه)

### لایه ۱: دود (Smoke) — curl
| چیست | روش |
|---|---|
| صفحه لود می‌شود؟ | `GET` → 200/302 |
| کرش سرور نیست؟ | بدنه بدون `Fatal/Exception/SQLSTATE` |
| محتوا وجود دارد؟ | بدنه > 100 کاراکتر |

### لایه ۲: مسیر خوش‌اقبال (Happy Path) — curl + DB
| چیست | روش |
|---|---|
| عملیات موفق با داده صحیح | `POST` با فیلدهای کامل |
| تغییر در DB رخ داد؟ | `SELECT` قبل/بعد از عملیات |
| پاسخ صحیح است؟ | JSON `success:true` یا redirect به مقصد درست |

### لایه ۳: مسیرهای شکست (Failure Paths) — curl
| چیست | روش |
|---|---|
| داده ناقص | `POST` بدون فیلد الزامی → 422 |
| داده نامعتبر | `POST` با مقدار غیرمجاز → 422 |
| بیش از سقف | مبلغ/تعداد بیش از حد → 422 |
| منبع ناموجود | ID = 99999 → 404/422 |

### لایه ۴: امنیت و مجوز (Security) — curl
| چیست | روش |
|---|---|
| دسترسی غیرمجاز | کاربر عادی → مسیر ادمین → 403/302 |
| CSRF محافظت | `POST` بدون token → رد |
| تزریق (Injection) | Payload SQLi/XSS → رد/escape |
| مالکیت منبع | کاربر A → منبع کاربر B → 403 |

### لایه ۵: موارد لبه (Edge Cases) — curl
| چیست | روش |
|---|---|
| مقدار صفر/منفی | amount=0, amount=-1 |
| مقدار خالی | string خالی |
| مقدار بسیار بزرگ | amount=999999999999 |
| تکرار عملیات | دو بار submit → idempotency |
| شرایط رقابتی (Race) | دو درخواست همزمان |

### لایه ۶: مرورگر (Browser) — Playwright
| چیست | روش |
|---|---|
| خطای کنسول JS نیست؟ | `page.on('console')` |
| خطای اجرای JS نیست؟ | `page.on('pageerror')` |
| asset failure نیست؟ | `page.on('requestfailed')` |
| DOM رندر شد؟ | `body.textContent().length > 100` |
| فرم قابل fill است؟ | `locator('input[name]').fill()` |
| دکمه کلیک می‌شود؟ | `locator('button').click()` |
| AJAX response درست است؟ | `page.waitForResponse()` |

### لایه ۷: یکپارچگی داده (Data Integrity) — DB
| چیست | روش |
|---|---|
| موجودی همخوان است؟ | `SUM(wallets) = SUM(transactions)` |
| رکورد یتیم نیست؟ | FK معتبر |
| enum درست است؟ | `status` در مقادیر مجاز |
| timestamp ست شد؟ | `created_at`, `updated_at` معتبر |

---

## فرمول تست هر بخش
```
تست‌های هر بخش = لایه ۱ + لایه ۲ + لایه ۳ + لایه ۴ + لایه ۵ + لایه ۶ + لایه ۷
حداقل سناریوها = ۳(moke) + ۲(happy) + ۴(failure) + ۳(security) + ۳(edge) + ۳(browser) + ۲(data) = ۲۰
```

## اجرا
- **لایه ۱ تا ۵ و ۷**: Python `scenario_*.py` با DB snapshot/restore
- **لایه ۶**: Playwright `browser_*.js` با Chromium
